# v1.2.0 开发记录

状态：v1.2.0 于 2026-10-05 发布，稳定源码位于 main，版本标签为 v1.2.0。Android versionCode 12；正式包使用 `xin.anji.hamlogbook`，调试包使用独立的 `xin.anji.hamlogbook.debug` 包名和 `1.2.0-debug` 版本名。面向用户的改动和安装说明见 [v1.2.0 发布说明](V1.2.0_UPDATE.md)。

## 本次改动

- 设备预设、亚音和各页的下拉选择统一使用应用内列表，带筛选、取消和键盘操作；保留手动输入。每次打开读取当前候选值，返回缓存页面时刷新设备列表，避免依赖 WebView 原生候选弹窗。
- 记录页“信号和频率”在我方发送、接收 RST 下方显示等宽占满一行的“默认频率”“从中继台选择”“优秀信号”。优秀信号将两项 RST 填为 59，并保存到当前草稿；中继列表分别显示接收、发射频率，选择后识别频段。
- 手动输入频率时即时识别当前目录内的波段，并同步可见的波段选择按钮，无须离开输入框。遵循已设置的操作证类别选项目录；输入中的不完整值不弹类别提示，完成录入后保留原有提示，未知频率保留手动波段选择。
- 频段列表只显示实际可选频段；“选择频段”仅作为未选时的提示，不出现在列表中。查询源选项文案更新为“QRZ.com（普通账号只能有限查询）”。
- 中继条目增加明确的“编辑”按钮，支持修改名称、收发频率、收发亚音、位置及备注，使用“保存修改 / 取消编辑”。保存更新原记录，取消不写入；删除当前编辑项时退出编辑，随后可正常添加新中继。
- “通联信息”增加整行“使用默认设备和功率”。在设置 → 台站资料与预设保存默认频率（MHz）、设备及功率（W）；仅在点击时填充，未配置的字段保留手填内容。
- 支持 HamQTH / QRZ 查询源和账号验证。Android 查询直接使用 CapacitorHttp，QRZ 密码通过 POST 提交，凭据使用 Android Keystore 加密保存。
- HamQTH 异常经纬度不会中断有效姓名、QTH 和网格的填充；查询过程中更改呼号会丢弃旧结果。网格优先使用服务返回的有效值，坐标仅用于缺少网格时补算。
- 个人信息备份升级为 schema 4，保存新增默认值、查询源及用户名，兼容 schema 1 / 2 / 3。新备份排除两种平台的密码，旧备份中的明文 HamQTH 密码只在 schema 1 / 2 的迁移中读取。
- 修正新建 QSO 页面错误显示“删除 QSO”按钮的情况；编辑记录时显示。
- 设置主页固定在标题和导航之间，正常尺寸下无多余滚动/回弹。小屏、横屏或大字体放不下内容时允许内容区内部滚动；设置子页继续正常滚动。顶部和底部适配 Capacitor 安全区变量。
- 外观偏好同步到 Android：启动期间系统栏按启动方案配色，进入页面后按网页白昼/黑夜模式配色；旋转、后台恢复和系统主题变化后重新应用，修正退出启动页时恢复成固定白昼的行为。
- 原生启动代码尝试显示用户所选方案的完整画面：在实际绘制且系统窗口退出后计时，至少展示一秒并等待网页就绪；3.5 秒总超时用于异常兜底。用户反馈冷启动页历史遗留问题仍未解决，当前实现尚未通过真机验收，继续作为待修复项；本轮仅调整频段选项和查询源文案。

启动处理依据：[Android 启动页迁移说明](https://developer.android.com/develop/ui/views/launch/splash-screen/migrate)、[持久启动主题接口](https://developer.android.com/reference/android/window/SplashScreen#setSplashScreenTheme(int))、[WebView 绘制状态回调](https://developer.android.com/reference/android/webkit/WebView#postVisualStateCallback(long,%20android.webkit.WebView.VisualStateCallback)) 与 [Capacitor SystemBars 安全区说明](https://capacitorjs.com/docs/apis/system-bars)。Android 12+ 系统自身的启动窗口仍可能先出现，随后交接到用户所选的完整画面；保留完整用户画面是本次修复目标。

## 查询源调查

Wavelog 的 [接入文档](https://docs.wavelog.org/user-guide/integrations/callsign-lookup/) 和 [QRZ 接入源码](https://github.com/wavelog/wavelog/blob/master/application/libraries/Qrz.php) 同样通过 XML 登录、缓存会话并查询呼号。其文档提到普通 QRZ 账号可以返回部分姓名和城市字段；[QRZ 官方规范](https://www.qrz.com/docs/xml/current_spec.html) 将未订阅账号定位为有限测试访问，完整资料需要 XML 订阅。因此本应用允许普通账号尝试并填入实际返回的资料，不承诺字段齐全或持续可用，也不会自动购买订阅。

当前 App 自动填写 QRZ 返回的姓名（优先昵称）、位置（城市、州、国家）和网格坐标。缺少有效网格时可以用有效经纬度计算网格。官方接口还可能提供地址、电子邮件、DXCC、CQ/ITU 分区及 QSL 信息等；当前通联表单没有接入这些字段。各呼号资料与账号权限决定实际返回内容，坐标可能是登记资料或估算位置，并非当前通联现场定位。

[HamQTH 官方文档](https://www.hamqth.com/developers) 说明旧 XML 接口仍支持现有应用。2026-10-05 实际读取未登录接口，得到 HTTP 200、XML“Username or password missing”和允许跨域的响应头。只能据此确认接口可达及响应格式；没有真实账号时不能证明完整登录和查询可用。本次保留免费 HamQTH 默认源并增加 QRZ 选项。

[Callook](https://callook.info/) 面向美国呼号；[HamDB](https://hamdb.org/) 首页列出的范围为 AU、CA、CZ、DE、US，不能据此作为中国呼号的通用替代。[LoTW 官方接口](https://lotw.arrl.org/lotw-help/developer-query-qsos-qsls/) 查询的是账户的 QSO/QSL 记录，不是同类公开呼号资料库。

- 独立 Chromium 浏览器回归：默认填充、优秀信号及草稿保存、中继编辑与取消、无效频率校验、修改后选择与应用、删除编辑项后重新添加、三轮真实页面切换、返回后预设刷新、筛选与取消；使用模拟账号和数据库验证 HamQTH/QRZ 登录、过期重试、资料填充及旧查询结果丢弃。
- 频段列表不显示占位项，初始未选和取消后仍保留空值，未选时保存仍有必填提示；QRZ 新文案可正常选择并查询。
- 频率输入框保持焦点时输入 50.500 / 144.370 / 434.650 MHz 即时选中 6m / 2m / 70cm；B 类设置下输入 14.270 MHz 即时选中 20m，逐字输入过程无中间值类别提示。
- 320 / 390 / 768 像素宽度的页面无横向溢出；390 像素页面截图已人工检查。
- 设置主页在 390×844、320×568、844×390、320×320 下无根页面滚动，小屏内容可访问；模拟上下 24px、左右 12px 安全区时标题/主题按钮/导航点击项均不被遮挡。浏览器模拟验证主题和启动样式先同步、再发送网页就绪通知；原生启动页与系统栏仍需真机观察。
- Android Debug APK 构建及 `lintDebug` 通过，APK 签名和 16 KB 对齐核验通过。离线首次检查缺少测试依赖，按原有版本补齐缓存后完整检查成功。
- 发布准备：Release 构建、7 项原生单元测试及 `lintRelease` 通过（0 错误、9 项原有警告）。正式包确认不可调试，包名为 `xin.anji.hamlogbook`、版本为 1.2.0 / 12；证书与长期正式密钥一致，41 个 Web 资源与源码一致，签名和 16 KB ZIP 对齐核验通过。准备时电脑没有连接 Android 设备；随后维护者简单测试正式包并确认发布，细项验收仍未逐项记录。

## 真机验收

1. 安装 Debug 包，可与正式版并存。正式版日志需要通过 ADIF 导出后导入调试版。
2. 保存两台设备、默认频率和功率。在主页填充一次，再依次切换历史、中继、设置并返回，反复选择设备、模式、频段、QSL 和亚音。
3. 添加收发频率不同的中继，点击“编辑”修改名称、频率、亚音、位置和备注并保存；再修改一次并取消，确认没有写入。主页分别选择更新后的接收和发射选项，核对频率和频段。
4. 核对三个快捷按钮在 RST 下方同一行占满宽度；“优秀信号”将发送和接收都填为 59。填写呼号后使用快捷填充，暂时离开并返回，确认草稿内容保留；编辑旧 QSO 时确认保存的是填入的新值。
5. 使用真实 HamQTH 账号“保存账号 → 验证账号 → 查询已知呼号”，确认姓名、位置和网格。断网、账号错误、呼号不存在时应给出提示，仍可离线保存。
6. 可选用普通 QRZ 账号尝试有限查询；没有返回资料时按提示处理。QRZ 订阅账号的完整查询仍需要实际验证。
7. 导出并恢复个人信息备份，核对新增预设、中继和查询源；账号密码需要重新填写。导出 ADIF 时功率应为数值，例如 `<TX_PWR:1>5`。
8. 设置主页在普通尺寸不应有多余下滑；横屏或大字体放不下时可以在内容区滚动，并能访问全部入口和项目链接。
9. 依次保存方案 A / B / C / D / E，结束进程后重开：系统窗口后必须显示相应的完整画面，而非只有系统图标与背景。正常启动完整画面至少可见一秒。特别检查 D 的“HAM LOGBOOK / 夜间通联记录”文字、E 的日志本画面，及网页白昼/黑夜切换时的系统栏；旧设置需要先打开一次应用同步到原生。
10. 旋转屏幕、切到后台再返回、改变系统主题，核对状态栏图标、标题和导航安全区；手动选定外观后不随系统改变。冷启动不应每次等满 3.5 秒，若发生请反馈；本次尚未完成真机画面验收。
11. 保持频率输入框焦点，输入 144.370 / 439.650 MHz，核对波段即时成为 2m / 70cm。对应操作证类别的选项目录中无该波段时，应保留原有类别约束和完成输入后的提示。

浏览器模拟和成功构建不能替代 Android WebView、Keystore、SQLite 及真实查询账号的验收。维护者已完成多轮 Debug 包测试，并简单测试正式签名包后确认发布；数据库升级、ADIF 导入导出及恢复仍待逐项验证。冷启动页继续作为已知问题保留在发布说明中。
